# Complete An x402 Payment

Use the operations and scopes published by the selected Resource Servers. Do
not assume a payment provider or account.

Inspect each selected Resource Server's discovery response before composing the
flow. If it advertises an Arazzo document with `Link: rel="describedby"` or
OpenAPI `externalDocs`, use its workflows to identify the service-local steps,
inputs, and header outputs. A workflow never grants authority and never fixes
which separate payment Resource must be used; select that Resource through
Realmroot discovery and request its exact published scopes.

Before starting, obtain permission for both the requested service and its
payment operation. Then complete the live flow without pausing:

1. Repeat the original request and capture its fresh `Payment-Required` header.
2. Send that header unchanged to the selected payment operation with one
   idempotency key.
   If the operation reports multiple compatible choices, select one advertised
   selection identifier based on the task's network and asset constraints, then
   retry the same requirement and idempotency key with that selection.
3. Capture the returned `Payment-Signature` header.
4. Send that signature unchanged with the original request.
5. Require the requested service to return success and capture its
   `Payment-Response` header.
6. Send that response unchanged to the payment confirmation operation.
7. Read the payment status and require it to be `settled`.

Use `--include` when response headers must be captured. Discard an expired
payment requirement and start again with a fresh one. Reuse an idempotency key
only when retrying the same payment.
