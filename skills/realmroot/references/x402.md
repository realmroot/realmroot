# x402 Paid Operations

Use this reference only when a target operation returns an x402 payment
requirement. Keep resource authorization, payment authorization, and the
business request as separate steps.

## Prepare Before The Live Challenge

1. Request the complete task-scoped access needed on the business Resource.
2. Discover the wallet Resource Server and request its budget and payment
   scopes.
3. Use the merchant's offer or an initial payment requirement to request a
   controller-approved budget constrained to the amount, merchant origin,
   recipient, network, and task lifetime.
4. Ensure both target credentials and the approved budget remain active long
   enough to finish the live payment exchange.

An initial payment requirement used to define policy is disposable. Obtain a
fresh requirement after approvals are ready.

## Complete The Timed Exchange

Execute these steps without an approval pause between them:

1. Repeat the merchant purchase request and capture its fresh
   `Payment-Required` response header with `--rsh-print h`.
2. Send that header unchanged to the wallet with a stable idempotency key.
3. Capture the wallet's `Payment-Signature` response header with
   `--rsh-print h`.
4. Forward that header unchanged to the same merchant request.
5. Require the merchant's delivered or settled success response.
6. Confirm settlement with the wallet when its contract exposes a confirmation
   operation.
7. Retry the original business request byte-for-byte unchanged.

Use the target OpenAPI documents for exact operation names and request bodies.
Extract one declared header line from Restish's header output; preserve its
value exactly and forward that response-header value.

## Freshness And Retry Rules

- Treat `maxTimeoutSeconds` as a hard deadline for the live exchange.
- Discard an expired payment requirement and every signature created for it.
- Reuse the same idempotency key only for an idempotent replay of the same
  wallet authorization. Use a new key for a new payment requirement.
- A wallet may reserve budget when it issues a signature. Obtain an active
  replacement budget before authorizing another requirement when the previous
  reservation consumed the available limit.
- Retry the business request only after the capacity or entitlement delivery is
  confirmed.
