# Restish Command Reference

Use this reference to discover the Restish commands supported by the FlareAuth
Management API. Product-specific OIDC client configuration examples belong in
the OIDC client guide.

These instructions require Restish v2. Upgrade Restish before using this skill;
Restish v1 is not supported.

The public Management API base path is:

```text
/api/management
```

The OpenAPI contract is generated by the server and served at:

```text
/api/management/openapi.json
```

## Connect And Authorize An API

First identify the deployment origin. `AUTH_ORIGIN` is the FlareAuth deployment
origin, such as a production custom domain or a `workers.dev` origin. Choose a
short `API_NAME` derived from that deployment host and confirm both values before
continuing.

```bash
AUTH_ORIGIN=https://auth.example.com
API_NAME=auth-example-com
restish --version
restish api connect "$API_NAME" "$AUTH_ORIGIN/api/management" --replace --yes
restish "$API_NAME" get-readiness --rsh-silent
```

The installed Restish version must start with `2.`. `api connect` discovers and
caches the OpenAPI contract. `--replace` applies the server-published v2
credential binding instead of preserving an incompatible profile migrated from
Restish v1. The readiness request starts browser authorization when no reusable
OAuth token is cached. Ask the user to complete that browser flow.

`API_NAME` must start with a letter or number and contain only letters,
numbers, underscores, and hyphens.

For a previously connected API, refresh the generated commands before use:

```bash
restish api sync API_NAME
```

## Built-In CLI Client

FlareAuth has a built-in public native client for Restish:

```text
client_id: flareauth-cli
redirect_uri: http://localhost:8484/callback
scopes: openid profile email offline_access management:read management:write
```

This client is for Restish/Management API automation through the standard
authorization-code browser callback. Do not modify this system-managed
application for product OIDC device login.

## Command Style

Use generated operation commands from the OpenAPI `operationId`s:

```bash
restish API_NAME --help
restish API_NAME OPERATION --help
restish API_NAME get-readiness
restish API_NAME list-applications
restish API_NAME get-application app_123
```

For JSON bodies, pass content through stdin:

```bash
restish API_NAME create-application \
  --rsh-validate \
  -o json < application.json
```

When generated commands are awkward or unavailable, use Restish generic verbs
with resource paths:

```bash
restish get API_NAME/applications
restish get API_NAME/applications/app_123
restish post API_NAME/applications < application.json
restish patch API_NAME/applications/app_123 < patch.json
restish delete API_NAME/applications/app_123
```

Use `-o json` when another tool or script will consume the result.

Use `--rsh-generate-body` to inspect a generated JSON example before writing a
request file. Use `--rsh-validate` on JSON create and update operations.

Use `restish doctor api API_NAME` when discovery, generated commands, profiles,
or authentication do not behave as expected. Use
`restish api auth inspect API_NAME --redact` for shareable authentication
diagnostics.
