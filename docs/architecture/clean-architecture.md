# Current Code Structure

This is the mutable implementation map for
[ADR 0003](../adr/0003-clean-architecture-dependency-direction.md). The
`server/` half follows the four-layer clean-architecture layout. Source-code
dependencies are enforced by `pnpm run lint:arch` in CI. Dependency Cruiser
uses SWC to scan `server/` and `shared/` because its native parser does not yet
support the repository's TypeScript 7 compiler. A TypeScript-AST check covers
the `src/` boundary because Dependency Cruiser's SWC parser cannot parse TSX.

## Layout

```
server/
  domain/          # Pure business rules. Plain TS; imports only domain/ + shared/.
                   #   errors, password, security/policy, connectors/provider-templates,
                   #   agents/capabilities
  usecases/        # Application operations as deps-first FUNCTIONS over ports:
                   #   foo(deps, input, { issuer }). No classes.
    ports.ts       # Interfaces + plain record types for everything past the process
                   #   boundary (repositories, gateways). No drizzle, no zod, no hono.
    deps.ts        # The Deps aggregate of all ports.
    <resource>.ts  # One usecase module per resource (+ <resource>-utils.ts helpers).
  adapters/
    repos/         # Drizzle repositories — the ONLY place the db schema is imported.
    gateways/      # External services: email, JWKS, secrets, OAuth request construction.
  http/            # Hono routes (by resource), zod validation, error mapping, auth
                   #   middleware, the app assembler, and the RPC schema/AppType.
                   #   Routes read deps via c.get('deps'); they never construct adapters.
  composition.ts   # createDeps(env, config): the request-free root, the ONLY place
                   #   adapters are constructed. Injected into context by depsMiddleware.
  worker.ts        # fetch entrypoint: validateEnv -> createDeps -> createApp(auth, deps, config).
  env.ts           # Env derived from the generated Cloudflare.Env (pnpm cf-typegen) + validateEnv.
  auth*.ts         # better-auth integration (owns its own tables + serves requests).
  db/              # drizzle schema + client factory (consumed by adapters/repos only).
shared/            # API contract: DTO types + pure helpers used by both halves.
src/               # React SPA (not governed by the layers).
```

## The dependency rule (enforced)

`http -> usecases -> domain`; `adapters -> usecases(ports) + domain`;
`composition -> everything`. Never the reverse. The exact rules live in
`.dependency-cruiser.cjs`:

- `domain/` imports only `domain/` and `shared/` (no frameworks, no I/O).
- `usecases/` never imports `hono`, `drizzle-orm`, `zod`, `better-auth`, or anything
  in `adapters/`, `http/`, `db/`, or `composition`.
- Drizzle schema is confined to `adapters/repos/` and `db/` — plus `server/auth*.ts`
  (the better-auth boundary owns its own tables; a named exception).
- `http/` never constructs adapters; it gets `deps` from context (`c.get('deps')`).
- `shared/` is a leaf and cannot import the server or SPA.
- The server cannot import the SPA. The SPA normally reaches the server over
  HTTP and currently has one allowed Hono RPC type import of `AppType` from
  `src/lib/api/index.ts`; `scripts/verify-frontend-boundary.mjs` rejects other
  SPA-to-server imports.

## Dependency injection

`composition.createDeps(env, config)` builds every adapter once (request-free, so the
fetch/scheduled entrypoints share it). `createApp(auth, deps, config)` registers a
deps middleware first (`c.set('deps', deps)`); routes call usecase functions with
`c.get('deps')`, passing request-bound values (issuer/origin from the request URL) as
explicit parameters.

## Path aliases

`@/* -> src/*`, `@server/* -> server/*`, `@shared/* -> shared/*`, defined identically
in `tsconfig.json` `paths` and `vite.config.ts` / `vitest.config.ts` `resolve.alias`.

## Env

`server/env.ts`: `Env` derives its binding fields from the wrangler-generated
`Cloudflare.Env` (`server/worker-configuration.d.ts`, gitignored, regenerated by
`pnpm cf-typegen` on postinstall). `EMAIL` is narrowed to our `SendEmail` wrapper and
the optional deployment config vars are declared by hand; `validateEnv` derives the
`RuntimeConfig`.

## Test Runtimes

The layers collapse into runtimes via vitest `projects` (`vitest.config.ts`):

- **unit** (node): server domain/usecases/adapters over fake ports + shared contracts +
  the faked server-flow tests. Coverage is collected here.
- **web** (jsdom): the React SPA (components, hooks, the api client) with the API mocked.
- **integration** (`@cloudflare/vitest-pool-workers`, real D1, production migrations
  applied): the crown in `server/integration/` — full `app.fetch` flows and real Better
  Auth sessions over real D1, faking nothing but the outward email/R2 gateways. Per
  resource: happy path + 401 + 403 + one validation failure (not the usecase branch matrix).

Cross-stack Playwright tests run the real SPA, Worker, authentication stack, and
isolated local D1. Behaviour selection and test-governance rules are maintained
in `AGENTS.md`, `specs/README.md`, and the feature files rather than duplicated
here.

## Migrations

`server/db/schema.ts` is the single source. `pnpm db:generate` (drizzle-kit) produces
migrations; the drizzle snapshot in `migrations/meta/` is baselined to the schema, so
`db:generate` reports "No schema changes" on a clean tree. The legacy numeric
`NNNN_*.sql` files remain the applied production history; generated migrations use a
timestamp prefix so they sort after them. CI runs `db:generate` and fails on a dirty
`migrations/` tree (schema changed without a committed migration).
